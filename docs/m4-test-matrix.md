# M4 reminder test matrix — 25 cases

**Status: Implementation complete. Device verification pending.**

Use the fillable device pack at
[`docs/m4-device-verification-pack.md`](m4-device-verification-pack.md) and the
command reference at [`docs/m4-device-commands.md`](m4-device-commands.md).

Status legend: **Pending** = not run on hardware (no Android device/emulator in
this environment). **Automated** = pure policy/mapper coverage exists, but the
native device path still needs the manual run. Do not mark a case passed from
unit tests alone.

Prerequisites:

- Android API 26+ device or emulator with Google Play services not required.
- Dev build `com.novatask.app.dev` installed from `pnpm android:dev` or
  `./gradlew assembleDevDebug`.
- Metro available for debug builds; use a release/dev bundle for app-killed tests.
- Nova → Developer tools → Reminder test lab and Reminder diagnostics open.
- `adb logcat -s NovaReminders` available for evidence.

## Recording evidence

For each case, record:

- Device model, Android API level, OEM skin, and build type.
- UTC timestamp and time zone.
- `adb logcat -s NovaReminders` excerpt.
- Diagnostics screenshot before/after.
- SQLite row state (`schedule_state`, `status`, `trigger_at`) and action-queue count.
- Pass/fail and any deviation.

The M4 acceptance checklist remains incomplete until all 25 rows are run on the
target Android hardware.

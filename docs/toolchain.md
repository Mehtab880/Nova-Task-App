# Toolchain

Pinned versions for Milestone M0. All versions are exact in `package.json`;
`pnpm-lock.yaml` is committed and CI installs with `--frozen-lockfile`.

## Runtime and package manager

| Tool         | Version          | Notes                                                            |
| ------------ | ---------------- | ---------------------------------------------------------------- |
| Node.js      | 24.18.0 (tested) | React Native 0.88 requires `^22.13.0                             |     | ^24.3.0 |     | >=26` |
| pnpm         | 10.34.7          | `node-linker=hoisted`; workspace protocol for `@nova/shared`     |
| TypeScript   | 6.0.3            | strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` |
| React        | 19.3.0           | Matches the React Native 0.88 template                           |
| React Native | 0.88.0           | Latest stable compatible with SDK 36 in this environment         |

`.npmrc`:

```ini
node-linker=hoisted
strict-peer-dependencies=false
auto-install-peers=true
resolution-mode=highest
```

Hoisted linking keeps React Native autolinking and Metro resolution predictable
in a monorepo. The trade-off is weaker pnpm isolation: do not rely on
undeclared dependencies.

`local.properties` is generated by Android Studio or Gradle and is git-ignored.

Because this is a pnpm monorepo, the Gradle build points at the hoisted
dependencies explicitly:

- `react.root` is `apps/mobile`, the JavaScript project root that owns
  `package.json` and `index.js`.
- `reactNativeDir`, `codegenDir`, and `cliFile` resolve inside the repository
  root `node_modules`.
- `hermesCommand` uses `node_modules/hermes-compiler/hermesc/%OS-BIN%/hermesc`
  so release bundling works with hoisted dependencies on Windows and Linux.
- Autolinking runs `node node_modules/@react-native-community/cli/build/bin.js
config` instead of the `npx` shim, which is not directly executable from
  Gradle on Windows.

Zod v4's ESM entry uses `export * as ns`; `@babel/plugin-transform-export-namespace-from`
is therefore enabled so Metro can bundle `@nova/shared` schemas in release.

## Fonts

Source of truth: `apps/mobile/assets/fonts/`.

| Token    | File                                          |
| -------- | --------------------------------------------- |
| Regular  | `PlusJakartaSans-Regular.ttf`                 |
| Medium   | `PlusJakartaSans-Medium.ttf`                  |
| SemiBold | `PlusJakartaSans-SemiBold.ttf`                |
| Bold     | `PlusJakartaSans-Bold.ttf`                    |
| Fallback | `Roboto-Regular.ttf` (registered as `Roboto`) |

The Gradle `copyNovaFonts` task copies them into
`android/app/src/main/assets/fonts/` before every build. `pnpm check:fonts`
parses `typography.ts`, validates the TTF signatures, and fails if any file is
missing. `allowFontScaling` is always on; `maxFontSizeMultiplier` is 2.0.

## Build environment variables

`babel-plugin-transform-inline-environment-variables` inlines only:

- `NOVA_APP_ENV` — `dev` | `staging` | `prod`
- `NOVA_API_BASE_URL` — public origin, no secrets
- `NOVA_ENABLE_M0_SPIKE` — `true` enables the dev-only SQLite spike

Rules:

1. Never put a secret in these variables; they end up in the JS bundle.
2. Release builds default to `prod` when `NOVA_APP_ENV` is unset (`__DEV__` is false).
3. Staging builds must set `NOVA_APP_ENV=staging` when bundling.
4. Reset Metro cache after changing values: `pnpm start -- --reset-cache`.

## Gradle tasks

```bash
cd apps/mobile/android
./gradlew tasks                 # discover variants
./gradlew assembleDevDebug
./gradlew assembleStagingDebug
./gradlew assembleProdRelease
./gradlew installDevDebug       # device/emulator
```

Release configuration:

- `minifyEnabled true` (R8 full mode)
- `shrinkResources true`
- `proguard-android-optimize.txt` + `proguard-rules.pro`
- signing: `keystore.properties` if present; otherwise an explicitly warned,
  non-distributable debug-key fallback. Use `-PrequireReleaseSigning=true` to
  fail closed. See [`android-release-signing.md`](android-release-signing.md).

## CI

`.github/workflows/ci.yml` has two jobs:

1. **quality**: pnpm cache, frozen install, typecheck, lint, format check, Jest,
   font check, Android config audit, gitleaks.
2. **android**: JDK 21, Android SDK 36, NDK/CMake, Gradle cache,
   `assembleDevDebug`, `assembleProdRelease`, APK `targetSdk` verification, and
   APK artifact upload.

## Troubleshooting

- **Metro cannot resolve `@/...`** — ensure Babel, tsconfig, and Metro aliases
  are unchanged; restart with `--reset-cache`.
- **Autolinking fails** — run `pnpm --filter @nova/mobile exec react-native config`.
  It must report `packageName: com.novatask.app` and the native dependencies.
- **NDK/CMake missing** — install the exact versions above; New Architecture
  compiles native code even when no custom native code exists.
- **`SDK location not found`** — set `ANDROID_HOME` or create
  `apps/mobile/android/local.properties`.
- **Release install fails with `INSTALL_FAILED_UPDATE_INCOMPATIBLE`** — uninstall
  the previous app with the same application ID.
- **R8 release crash** — reproduce with `assembleProdRelease`, inspect the
  mapping file, and add narrowly scoped keep rules. Do not disable R8.
